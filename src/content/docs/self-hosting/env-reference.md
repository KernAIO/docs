---
title: Environment reference
description: Every variable in the self-host .env file and what it controls.
---

`install.sh` creates `~/kern/.env` from `.env.example` and fills in secrets. The variables below are read by `docker-compose.yml` and passed to the services. Restart with `docker compose up -d` after changing any of them.

## Public URL & TLS

| Variable | Example | Purpose |
|---|---|---|
| `KERN_DOMAIN` | `kern.example.com` | Host name Caddy serves. Use an IP for LAN installs. |
| `KERN_BASE_URL` | `https://kern.example.com` | Public URL users open. Used in emails, OAuth callbacks, CORS and the PWA. Must match `KERN_DOMAIN`. |
| `ACME_EMAIL` | `admin@example.com` | Contact email for Let's Encrypt. Set to `internal` for a self-signed certificate on IP/LAN installs. |

## Release

| Variable | Default | Purpose |
|---|---|---|
| `KERN_VERSION` | `latest` | Image tag for all `ghcr.io/kernalo/*` services. Pin to a version to control upgrades. |

## Secrets (generated by `install.sh`)

| Variable | Purpose |
|---|---|
| `KERN_SECRET` | 32+ bytes. Master secret from which per-purpose keys are derived (AES-256-GCM for stored secrets, HS256 for service-to-service tokens). **Do not lose or rotate casually** — stored provider passwords and IMAP credentials are encrypted with keys derived from it. |
| `BETTER_AUTH_SECRET` | Session/JWT signing secret for the identity layer. |
| `POSTGRES_PASSWORD` | Password of the Postgres role used by all services. |
| `S3_SECRET_KEY` | MinIO root password / S3 secret key. |
| `LIVEKIT_API_KEY`, `LIVEKIT_API_SECRET` | Credentials services use to mint LiveKit room tokens (calls profile). |

Generate replacements with `openssl rand -hex 32`.

## Postgres

| Variable | Default | Purpose |
|---|---|---|
| `POSTGRES_USER` | `kern` | Role name. |
| `POSTGRES_DB` | `kern` | Database name. Each module uses its own schema (`mod_<id>`) inside it. |

The compose file assembles `DATABASE_URL=postgres://$POSTGRES_USER:$POSTGRES_PASSWORD@postgres:5432/$POSTGRES_DB` for the services. To use an external Postgres 18 (with `pgvector`, `pg_trgm`, `ltree`, `pgcrypto`), remove the `postgres` service and set `DATABASE_URL` directly in the shared environment block.

## Object storage

| Variable | Default | Purpose |
|---|---|---|
| `S3_ENDPOINT` | `http://minio:9000` | Internal S3 endpoint services upload to. |
| `S3_PUBLIC_ENDPOINT` | `https://kern.example.com/s3` | Endpoint embedded in presigned URLs handed to browsers (Caddy proxies `/s3/*` to MinIO). |
| `S3_REGION` | `us-east-1` | Region (any value for MinIO). |
| `S3_BUCKET` | `kern` | Bucket name (created by `minio-init`). |
| `S3_ACCESS_KEY` | `kern` | Access key / MinIO root user. |

Point these at AWS S3, R2, GCS (S3 mode) or any compatible store to run without MinIO.

## Outbound email (instance default)

| Variable | Example | Purpose |
|---|---|---|
| `SMTP_URL` | `smtps://user:pass@smtp.example.com:465` | Platform SMTP used for sign-in emails, invitations and any workspace that has not configured its own provider. |
| `MAIL_FROM` | `"Kern <no-reply@kern.example.com>"` | Default sender. |

Workspaces can override this with their own SMTP/Mailgun/SES/Postmark/Resend configuration in **Workspace settings → Mail**.

## First admin

| Variable | Purpose |
|---|---|
| `KERN_ADMIN_EMAIL` | If set, an instance admin with this email is created on first boot. |
| `KERN_ADMIN_PASSWORD` | Its initial password. Change it after signing in; you may then blank both variables. |

## Derived / internal variables

The compose file also sets, for every service: `NODE_ENV=production`, `NATS_URL=nats://nats:4222`, `VALKEY_URL=redis://valkey:6379`, `BETTER_AUTH_URL=$KERN_BASE_URL`, `CORE_URL`, `CHAT_URL`, `MAIL_URL`, `COLLAB_URL` (internal service addresses) and `LIVEKIT_URL=ws://livekit:7880`. The web app additionally receives `ORIGIN`, `PUBLIC_API_URL`, `PUBLIC_WS_URL` and `PUBLIC_COLLAB_URL`, all derived from `KERN_BASE_URL`. You normally never edit these.
